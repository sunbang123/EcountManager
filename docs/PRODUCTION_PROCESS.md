# Ecount Manager 제작 프로세스

## 제품 원칙

1차 버전은 Ecount 데이터를 변경하지 않는 읽기 전용 뷰어다. 전화 응대 중 고객을 찾고, 기존 거래 문의와 신규 주문 상담에 필요한 정보를 한 화면에서 빠르게 확인하는 것을 목표로 한다.

## 1. 기반 구조와 화면 골격 — 완료

- .NET 8 WPF 프로젝트와 MVVM 구조 구성
- 고객 검색, 고객 요약, 판매, 신규 주문, 채권 화면 구현
- 샘플 데이터로 전체 상담 흐름 검증
- 완료 기준: 앱 실행, 고객 전환, 각 표의 검색·필터가 정상 동작

## 2. Ecount API 사양 확정 — 공식 조회 범위 확정

- 회사 코드, 인증 방식, Zone 및 세션 만료 정책 확인
- 공식 제공 범위인 품목, 재고, 창고별 재고 조회의 필드 매핑
- 호출 제한, 조회 기간, 페이지 처리 방식 확인
- 완료 기준: API별 요청·응답 예제와 내부 모델 매핑표 작성

## 3. 실제 API 연동 — 클라이언트 구현 완료, 계정 검증 대기

- 인증 세션 관리와 안전한 자격증명 저장
- Zone, 로그인 세션, 품목, 재고, 창고별 재고 조회 서비스 구현
- 오류, 타임아웃, 재시도 및 부분 로딩 처리
- 완료 기준: 사용자의 테스트 인증키로 실제 데이터 조회 및 응답 필드 검증

## 4. 상담 검색 최적화

- 상호명 초성·부분 검색과 전화번호 검색
- 품목, 규격, 금액, 기간, 담당자 복합 필터
- 품목코드, 품목명, 규격, 바코드, 창고명 통합 검색
- 로컬 상담 메모와 생성시간순 목록 제공
- 완료 기준: 주요 상담 정보에 3회 이하의 입력 또는 클릭으로 접근

## 5. 보안과 운영 준비

- API 키와 회사 정보의 소스 코드 분리
- 사용자별 조회 권한과 민감정보 마스킹 검토
- 로그에 인증정보와 개인정보가 남지 않도록 점검
- 완료 기준: 배포 설정과 보안 점검표 통과

## 6. 검증과 배포

- 실제 영업 시나리오 기반 사용자 테스트
- 대량 거래 고객의 성능과 API 장애 상황 검증
- 사내 배포 패키지, 버전 표시, 업데이트 절차 마련
- 완료 기준: 영업팀 파일럿 사용자 승인 후 1.0 배포

## 다음 입력이 필요한 항목

- 사용할 Ecount API 문서 또는 실제 응답 샘플
- 회사의 가격 결정 규칙(기준가, 고객별 단가, 부가세 포함 여부)
- 영업팀이 가장 자주 사용하는 검색 조건과 필수 표시 필드
